# Krong Dev 블로그 게시글 작성 템플릿

이 템플릿은 `Express 미들웨어 파이프라인과 Node.js 이벤트 루프` 게시글을 기준으로 작성된 스타일 가이드입니다.
새 게시글 작성 시 아래 규칙을 모두 따르세요.

---

## 1. frontmatter

```mdx
---
title: "게시글 제목"
description: "게시글 한 줄 요약. 독자가 읽기 전 무엇을 얻는지 알 수 있도록."
date: "YYYY-MM-DD"
tags: ["태그1", "태그2"]
image: "./images/이미지파일명.jpg"
---
```

**규칙**
- `title`: 키워드 중심, 간결하게. 부제목 형식(`A와 B`) 허용
- `description`: 1~2문장. "~를 정리합니다" 형태로 마무리
- `tags`: 2~4개. 기술 스택 또는 카테고리 단어만
- `image`: 항상 포함. 경로는 `./images/` 기준

---

## 2. 도입부

```mdx
(본문 바로 시작. # 제목 반복 없음)

Node.js로 백엔드를 시작하면서 가장 먼저 부딪힌 두 가지 질문이 있었습니다.

> 첫 번째 질문

> 두 번째 질문

이 글에서는 [주제A]와 [주제B]를 **직접 실험한 결과**를 바탕으로 정리합니다.

---
```

**규칙**
- frontmatter 아래 `# 제목` 반복 없음. 바로 본문 시작
- 1인칭 경험 서술로 시작 ("~를 시작하면서", "~를 접했을 때")
- 핵심 질문 1~2개를 `>` blockquote로 제시
- "이 글에서는 ~를 정리합니다" 형태로 글의 범위 선언
- 도입부 끝에 `---` 구분선

---

## 3. 본문 구조

### 섹션 구분

```mdx
# 대주제 (h1) — 글 전체에서 2~3개
### 소주제 (h3) — #, ## 바로 아래는 <br /> 생략

본문 내용...

<br />

### 소주제 (본문 아래에서는 <br /> 사용)

## 중간 대주제 (h2)
### 소주제
```

**규칙**
- h1(`#`): 글 전체를 나누는 큰 챕터. 2~3개 이내
- h2(`##`): 실험 섹션처럼 h1 아래의 독립 단위
- h3(`###`): 소항목. h1 또는 h2 안에서 세부 설명. **h3 위에 `<br />`로 여백 추가** (`#`, `##`, 인용구 아래는 제외)
- h4 이하 사용 금지

---

### 설명 문단

```mdx
여기서 중요한 건 Express가 **우선순위 엔진이 아니라 순차 탐색 구조**라는 점입니다.
등록된 미들웨어를 위에서 아래로 순서대로 실행하고, `next()`를 호출하면 다음 미들웨어로 넘어갑니다.
```

**규칙**
- 핵심 개념은 `**굵게**` 강조. 남용 금지 (문단당 1~2개)
- **형광펜 하이라이트**는 `<mark>내용</mark>` 사용. **문장이 아닌 헤딩(`#`, `##`, `###`)에만** 사용. 글 전체에서 꼭 필요한 핵심 소제목에만 제한적으로 적용 (2~3개 이내)
  - 예: `### <mark>Provider와 Dependency Injection</mark>`
- **툴팁**은 `<Tooltip note="설명">내용</Tooltip>` 사용. MDX 상단에 `import Tooltip from "@/components/ui/Tooltip.astro"` 추가
- 괄호가 포함된 강조(예: `정확히 일치(Exact Match)`)는 항상 `<strong>...</strong>` 사용. `**...()**` 형태는 MDX 렌더링이 깨질 수 있으므로 금지. Tooltip 안의 굵은 글씨도 동일
- 코드, 명령어, 파일명은 인라인 코드 `` `backtick` `` 처리
- 문단은 2~4문장. 길면 나눈다

---

### 다이어그램 / 흐름 표현

```mdx
```text
Request
  ↓
requestId    →  요청 추적용 ID 부여
  ↓
logger       →  접근 로그 기록
  ↓
Response
```
```

**규칙**
- 흐름도는 항상 ` ```text ` 코드블럭 사용
- 화살표는 `↓` (세로) 또는 `→` (설명 연결)
- 한 줄에 항목명 + `→` + 한 줄 설명 형식 유지

---

### 표

```mdx
| 분기 | 코드 | 의미 |
|------|------|------|
| 다음으로 넘김 | `next()` | 다음 미들웨어로 제어권 이동 |
| 여기서 응답 | `res.json(...)` | 응답 후 체인 종료 |
```

**규칙**
- 3열 이내 권장
- 코드는 셀 안에서도 `` `backtick` ``
- 표 앞뒤로 빈 줄 1개

---

### 코드블럭

```mdx
```typescript
import { Request, Response, NextFunction } from "express";

export const errorMiddleware = (
  err: Error,
  _req: Request,
  res: Response,
  _next: NextFunction,
) => {
  res.status(500).json({ ok: false, message: err.message });
};
```
```

**규칙**
- 언어 명시 필수: `typescript`, `bash`, `text`, `cjs` 등
- 사용하지 않는 인자는 `_` prefix
- 주석은 설명이 필요한 줄에만. 과도한 주석 금지
- 코드블럭 앞뒤 빈 줄 1개

---

### 실험 섹션 구조

실험이 포함된 섹션은 아래 순서를 반드시 따릅니다.

```mdx
### 실험 : [실험 이름]

[실험 목적 1~2문장]

```typescript
// 실험 코드
```

**결과** : [결과 서술. 수치나 관찰 내용 포함]

![실험 결과](/images/폴더명/번호.png)

[결과 해석 또는 원인 분석]
```

**규칙**
- 실험 제목은 `### 실험 :` 으로 시작
- 코드 → 결과 선언 → 이미지 → 해석 순서 고정
- `**결과** :` 볼드 처리 후 바로 서술
- 이미지 경로: `/images/폴더명/번호.png` (번호는 순서대로)
- 실험 간 구분은 `<br />` 1개

---

### 이미지

```mdx
![실행 결과](/images/study-nodejs-1st/1.png)
```

**규칙**
- alt text는 `실행 결과` 또는 `실험 결과 확인하기` 통일
- 경로: `/images/게시글식별자/번호.png`
- 캡션 별도 추가 없음 (앞뒤 텍스트로 설명)

### 이미지 주석 처리

이미지 파일이 아직 준비되지 않았거나, 노션/외부 첨부파일 링크인 경우 HTML 주석으로 감싸서 주석 처리합니다.

```mdx
<!-- ![실행 결과](/images/게시글식별자/번호.png) -->
```

**규칙**
- 이미지 파일이 `public/images/` 에 없는 경우 `<!-- -->` HTML 주석으로 감싸서 주석 처리
- 주석 처리된 이미지는 실제 파일이 추가된 후 주석을 해제
- 주석 처리된 이미지도 경로 규칙(`/images/게시글식별자/번호.png`)과 alt text 규칙은 동일하게 적용

### 동영상

```mdx
import Video from "@/components/ui/Video.astro";

<Video src="/videos/게시글식별자/번호.mp4" />
```

**규칙**
- 원본 `.mov` 파일은 `raw-videos/게시글식별자/` 폴더에 저장 (git-ignored)
- `pnpm video:build` 또는 `pnpm build` 시 ffmpeg로 `public/videos/`에 `.mp4`로 자동 변환
- MDX 상단에 `import Video from "@/components/ui/Video.astro"` 추가
- `<Video>` 컴포넌트 사용 (런타임 JS 없음, `<video>` 태그만 렌더링)
- `poster` prop으로 썸네일 지정 가능 (선택)

## 4. 마무리 섹션

```mdx
---

## 마치며

[글 전체 흐름을 1~2문장으로 연결 요약]

직접 실험하면서 두 가지가 확실히 와닿았습니다.

- [핵심 인사이트 1]
- [핵심 인사이트 2]

다음 글에서는 [다음 주제]에 대해 정리할 예정입니다.
```

**규칙**
- 항상 `---` 구분선 후 `## 마치며`
- 글 전체 요약 → 실험/학습 인사이트 bullet → 다음 글 예고 순서
- 인사이트는 bullet 2~3개. 학습하면서 "확실히 와닿은" 것만
- 다음 글 예고는 1문장으로

---

## 5. 전체 톤 & 문체

| 항목 | 규칙 |
|------|------|
| 문체 | 합쇼체 (`~습니다`, `~합니다`). 구어체 혼용 금지 |
| 시점 | 1인칭 경험 서술 중심 |
| 길이 | 섹션당 설명 3~5문장. 장황하게 늘리지 않음 |
| 강조 | `**굵게**`는 핵심 개념만. 문단당 1~2개 초과 금지 |
| 링크 | 외부 도구, 공식 문서, 관련 게시글에만 사용 |
| 이모지 | 사용 금지 |
| 번호 목록 | 순서가 중요한 단계에만 사용. 그 외엔 bullet(`-`) |

---

## 6. 금지 사항

- `# 제목`을 frontmatter 아래에 반복하지 않는다
- "~에 대해 알아보겠습니다", "~를 살펴보겠습니다" 같은 형식적 문장 사용 금지
- 결론 없이 나열만 하는 섹션 금지. 모든 실험엔 해석이 따라야 한다
- 노션 원본을 그대로 복붙하지 않는다. 블로그 독자 시점으로 재서술한다
- 학습 노트 형식(체크박스, 표 위주 정리)을 그대로 옮기지 않는다
