# Krong Dev 아카이브 작성 컨벤션

아카이브(`/archive/`)는 블로그 글보다 가볍게 남기는 짧은 글입니다.
글은 `src/content/post/archive/{slug}.md`에 두고, 링크 블록 같은 컴포넌트가 필요하면 `.mdx`로 씁니다.

---

## 1. frontmatter

```yaml
---
title: "글 제목"
date: 2026-03-20T16:33:34+09:00 # 시간까지, KST 오프셋(+09:00) 필수
icon: "lucide:code-xml" # 아래 「아이콘」 규칙
tags: ["배움일기", "React"]
image: "../../../assets/archive/{slug}/cover.jpg" # 선택. 있으면 이미지 카드
type: quote # 선택. 인용 글만 (quote, author 함께)
---
```

- 본문 이미지는 `src/assets/archive/{slug}/`에 두고 상대 경로로 넣습니다. 외부 이미지 URL은 쓰지 않습니다.
  - 파일명은 대표 이미지 `cover.*`, 본문 이미지는 나오는 순서대로 `1.png`, `2.png` …
  - 본문에는 `![](../../../assets/archive/{slug}/1.png)`처럼 넣고, 앞뒤에 빈 줄을 둡니다.
- 목록 필터 칩은 `배움일기`, `알고리즘`, `코딩테스트`, `회고`, `TIL`, `사용후기`만 노출합니다(`src/lib/archive.ts`의 `ARCHIVE_FILTER_TAGS`).
- IDE·에디터·플러그인·도구를 직접 써 본 경험은 첫 태그를 `사용후기`로 둡니다.

---

## 2. 메인 타이틀 아래 구분선

본문 맨 위에 `---`를 넣어 제목과 본문을 구분합니다. (`.mdx`면 import 다음 줄)

```md
---
title: "..."
---

---

본문 시작
```

---

## 3. 본문 서식

- **단락:** 같은 흐름의 문장은 빈 줄 없이 이어 쓰고, 주제가 바뀔 때만 빈 줄로 나눕니다.
- **소제목:** `##`을 씁니다. (`###` 쓰지 않음)
- **tags:** 쉼표 뒤에 공백을 둡니다. `["배움일기", "React"]`
- **목록:** 마커는 `-`, 항목 사이에 빈 줄을 넣지 않고 하위 목록은 2칸 들여씁니다. 인용(`>`) 안의 목록도 같습니다.
  - 항목에서 줄을 바꿔 이어 쓰는 문장도 2칸 들여씁니다. 들여쓰지 않으면 항목 밖 문장처럼 읽힙니다.
  - 목록 앞뒤(숫자 목록 포함)에는 빈 줄을 둡니다.
- **목록은 나열에만:** 서술 문장과 "어떻게 해결할까?" 같은 질문형 소주제는 목록으로 쓰지 않고, 앞뒤 빈 줄을 둔 단독 단락으로 씁니다. 실제로 나열되는 항목만 목록으로 남깁니다.
  - 목록을 정리하는 문장("즉, …", "그래서 …")은 목록 안에 들여쓰지 않고, 목록 뒤 단락으로 뺍니다.
- **질문과 답:** `질문? : 답`처럼 한 줄에 붙이지 않고 질문 단락과 답 단락으로 나눕니다. 답의 핵심 용어는 굵게 씁니다.
- **살짝 띄우기:** 같은 단락·항목 안에서 간격이 필요하면 `<br>`을 단독 줄로 넣습니다. 목록 안이면 항목 들여쓰기에 맞춥니다.
- **목록 속 코드 블록:** 앞뒤에 빈 줄을 두고, 항목 내용 들여쓰기(2칸)에 맞춥니다.
- **코드 블록:** Prettier 기준으로 씁니다(큰따옴표, 세미콜론, 2칸 들여쓰기). 코드 안의 설명은 `// 주석`으로 적습니다.
- **인라인 코드:** API·메서드 이름은 문장 속에서도 인라인 코드로 감쌉니다. `` `Promise.race()` ``
  - HTTP 상태 코드(`` `401` ``, `` `4xx` ``), 헤더·옵션 값(`` `no-store` ``), HTML 속성(`` `hidden` ``)도 같습니다.
- **양방향 화살표:** `<->` 대신 `↔`을 씁니다.
- **이스케이프:** `sliced\_arr`, `nums\[index\]`처럼 불필요한 `\`는 지웁니다.

```md
<!-- ❌ -->
*   항목
이어지는 문장

- 원인은 무엇일까?
    - 서술 문장

<!-- ✅ -->
- 항목
  이어지는 문장
  - 하위 항목

원인은 무엇일까?

서술 문장
```

## 4. 아이콘

| 주제                                            | 아이콘                                        |
| ----------------------------------------------- | --------------------------------------------- |
| LeetCode·코딩 테스트                            | `lucide:copy`                                 |
| git·GitHub                                      | `lucide:git-*` 중 상황에 맞는 것 (예: `git-compare`, `git-merge`) |
| 로그인·보안·인증 등 개인정보가 들어간 주제      | `lucide:key-round`                            |

| DOM·알고리즘 등 구조에 대한 주제                | `lucide:network`                              |
| React·Next.js·프론트엔드 라이브러리(React Hook Form 등) | `lucide:atom`                          |
| Figma·database(Supabase) 등 명확한 주제         | 주제에 맞는 아이콘 (`figma`, `database` …)    |
| 나머지                                          | `lucide:code-xml`                             |

## 5. 굵게 (`**문자**`)

굵게 안에 `()` 같은 기호가 들어가 기호와 한글이 맞붙으면 `**`가 그대로 보입니다.
이때는 `<strong>`으로 감쌉니다. (블로그 글도 동일)

```md
<!-- ❌ ** 가 그대로 렌더링 -->
**race condition(경쟁 상태)**이나

<!-- ✅ -->
<strong>race condition(경쟁 상태)</strong>이나
```

## 6. 링크

- `링크 :`, `출처 :` 뒤에 붙는 링크와 문장 속 링크는 지금처럼 하이퍼링크 텍스트로 둡니다.

  ```md
  문제 링크 : [https://leetcode.com/problems/...](https://leetcode.com/problems/...)
  ```

- "자세한 내용은 …" 처럼 참고 자료로 거는 링크와 **글 최하단 링크**는 링크 블록(`LinkCard`)을 씁니다. (`.mdx` 필요)

  ```mdx
  import LinkCard from "@/components/ui/LinkCard.astro";

  **\*태스크 큐**에 대한 자세한 내용은 MDN: 태스크 큐

  <LinkCard url="https://developer.mozilla.org/ko/docs/Web/API/HTML_DOM_API/Microtask_guide" />
  ```

## 7. 카드 UI (자동)

목록 카드는 frontmatter에 따라 자동으로 정해집니다. 따로 지정하지 않습니다.

| 조건                         | 카드          |
| ---------------------------- | ------------- |
| `type: quote`                | 인용 카드     |
| `image` 있음                 | 이미지 카드   |
| 18:00~06:00(KST) 사이 작성   | 다크 카드     |
| 그 외                        | 기본 흰 카드  |
